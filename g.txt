4. Security, reliability, and cost
Networking
The VPC is separated into public, EKS-private, platform, and database subnets. The private and platform subnets share one NAT Gateway; the database subnets have no default internet route. 
terraform-infra.txt
terraform-infra.txt

This is a sensible cost-conscious lab design. The trade-off is that one NAT Gateway creates an Availability Zone dependency and ongoing cost. Retain it if the trade-off is acceptable; use two NAT Gateways if stronger AZ-level outbound resilience is required.

ECR lifecycle and rollback
The ECR repository uses immutable image tags, scan-on-push, and a lifecycle policy that expires untagged images after seven days and retains the latest 20 tagged images. 
terraform-infra.txt

Immutability is useful for traceability. However, the 20-image retention rule can expire an older image needed for rollback. Make the retention policy match the rollback window and release-tagging strategy before relying on automatic rollback.

Resource sizing
The EKS node groups use t3.small instances, and Jenkins has a t3.small controller. Nexus and SonarQube use t3.medium instances. The persistent EBS volumes are 10 GiB for Jenkins, 30 GiB for Nexus, and 30 GiB for SonarQube.

These are starting sizes, not verified capacity requirements. Maven builds, Java application pods, SonarQube analysis, Nexus artifact retention, and observability can exceed the available memory or disk. Measure usage and set monitoring and capacity thresholds before treating these as stable production sizes.

Security groups and IAM
Jenkins, Nexus, and SonarQube UIs are restricted to the Client VPN CIDR, while RDS MySQL accepts traffic from the application node security group. The custom security groups allow unrestricted outbound IPv4 traffic.
